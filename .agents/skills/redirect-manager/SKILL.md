# /digital-marketing-pro:redirect-manager

## Objectif

Gérer les redirections d'URL sur le site web. Créer de nouvelles redirections 301/302, auditer les redirections existantes pour détecter les chaînes et les boucles, corriger les chemins de redirection cassés, et déployer les changements via le MCP CMS connecté. Couvre les migrations de site, la restructuration d'URL et la maintenance continue des redirections. Une mauvaise gestion des redirections est l'une des causes les plus courantes de perte de trafic SEO — les chaînes diluent le link equity, les boucles créent des erreurs de crawl, et les redirections cassées renvoient des 404 pour des URL précédemment indexées. Cette commande fournit une gestion systématique du cycle de vie des redirections, de la création à l'audit et à la réparation.

## Porte d'exécution (OBLIGATOIRE — ne peut pas être contournée)

1. Présenter l'aperçu complet — chaque redirection à créer/mettre à jour/supprimer avec l'état actuel vs proposé et le rayon d'impact à l'échelle du site — comme un **résumé d'exécution** avant de toucher à une règle en production.
2. L'utilisateur doit taper `yes` (ou une approbation explicite équivalente). TOUTE autre entrée — ambiguë, implicite, partielle ou absente — annule l'exécution.
3. Ne jamais procéder sur une entrée ambiguë. Ne jamais relancer automatiquement une exécution échouée ; un échec nécessite une revue humaine avant toute nouvelle tentative.
4. Enregistrer l'approbation avec `python "${CLAUDE_PLUGIN_ROOT}/scripts/approval-manager.py" --brand {slug} --action create-approval --data '{"risk_level":"<tier>","summary":"..."}'` **avant** l'exécution, puis `python "${CLAUDE_PLUGIN_ROOT}/scripts/approval-manager.py" --brand {slug} --action mark-executed --id {approval_id}` une fois que la plateforme confirme le succès.

## Entrées requises

L'utilisateur doit fournir (ou se voir demander) :

- **Action de redirection** : L'opération à effectuer — `create` (créer de nouvelles redirections), `audit` (scanner toutes les redirections existantes pour détecter des problèmes), `fix` (résoudre les chaînes, boucles et cibles cassées trouvées lors de l'audit), ou `bulk-import` (importer une carte de redirections depuis un CSV ou une Google Sheet pour les migrations). Plusieurs actions peuvent être enchaînées (par ex. audit puis fix)
- **URL(s) source(s)** : Pour create et bulk-import — la ou les URL qui doivent rediriger. Peuvent être des URL exactes, des motifs d'URL avec wildcards (par ex. `/old-blog/*` vers `/blog/*`), ou des expressions régulières pour une correspondance complexe. Pour audit et fix, les URL sources sont découvertes automatiquement depuis le CMS
- **URL(s) cible(s)** : Pour create et bulk-import — la ou les URL de destination vers lesquelles les utilisateurs et les moteurs de recherche doivent être envoyés. Doivent être des URL en ligne, accessibles, renvoyant un statut 200. Pour bulk-import, fournies sous forme de paires source-cible dans le fichier d'import
- **Type de redirection** : `301` (permanente — à utiliser pour les changements d'URL permanents, les migrations de domaine, les passages à HTTPS et les restructurations d'URL) ou `302` (temporaire — à utiliser pour les tests A/B, le contenu saisonnier, les pages de maintenance ou les redirections géographiques). La valeur par défaut est 301 si non spécifié
- **Plateforme CMS** : `wordpress` ou `webflow` — doit avoir le MCP CMS correspondant connecté. Pour WordPress, spécifier la méthode de gestion des redirections : plugin Redirection, redirections RankMath, redirections Yoast Premium, ou `.htaccess` direct. Pour Webflow, l'API de redirection native est utilisée

## Processus

1. **Charger le contexte de la marque** : Lire `~/.claude-marketing/brands/_active-brand.json` pour obtenir le slug actif, puis charger `~/.claude-marketing/brands/{slug}/profile.json`. Appliquer la voix de marque, les règles de conformité pour les marchés cibles (`skills/context-engine/compliance-rules.md`), et le contexte sectoriel. Vérifier également les guidelines à `~/.claude-marketing/brands/{slug}/guidelines/_manifest.json` — si présentes, charger les restrictions. Vérifier les SOP d'agence à `~/.claude-marketing/sops/`. Si aucune marque n'existe, demander : « Configurer d'abord une marque (/digital-marketing-pro:brand-setup) ? » — ou continuer avec les valeurs par défaut.
2. **Pour create : valider les URL sources et cibles** : Confirmer que l'URL source existe ou a été précédemment indexée (vérifier GSC pour les données historiques), vérifier que l'URL cible est en ligne et renvoie un statut 200, vérifier qu'aucune redirection n'est déjà configurée pour l'URL source afin d'éviter les doublons, et vérifier si la redirection proposée créerait une chaîne (la source redirige vers une URL intermédiaire qui redirige elle-même ailleurs). Pour bulk-import, valider chaque paire source-cible du fichier d'import et signaler tout problème avant de continuer.
3. **Pour audit : parcourir toutes les redirections existantes** : Interroger l'API du CMS pour récupérer chaque règle de redirection configurée. Pour chaque redirection, tester le chemin complet en le suivant jusqu'à sa destination finale. Détecter les chaînes (plus d'un saut — par ex. A redirige vers B qui redirige vers C), les boucles (A redirige vers B qui redirige vers A, ou des chemins circulaires plus longs), les redirections pointant vers des pages d'erreur 4xx ou 5xx, les motifs de redirection en cascade qui gaspillent le budget de crawl, les redirections de protocole mixte (HTTP vers HTTPS vers HTTP), et les redirections avec une gestion excessive des paramètres de requête.
4. **Pour fix : résoudre les problèmes détectés** : Pour les chaînes — mettre à jour la première redirection pour qu'elle pointe directement vers l'URL de destination finale, éliminant les sauts intermédiaires. Pour les boucles — briser le cycle en identifiant la bonne destination finale et en mettant à jour ou en supprimant la règle en boucle. Pour les cibles cassées — identifier la bonne destination en ligne (vérifier les changements d'URL, le contenu archivé, ou les pages de remplacement) et mettre à jour la redirection, ou signaler pour revue manuelle si aucune cible claire n'existe. Pour les doublons — supprimer les règles redondantes, en conservant la plus récemment créée ou la correspondance la plus spécifique.
5. **Créer la porte d'approbation** : Présenter tous les changements de redirection proposés avec l'état actuel et l'état proposé — nouvelles redirections à créer (source, cible, type), corrections de chaînes (chemin actuel vs chemin simplifié avec le nombre de sauts réduits), résolutions de boucles (cycle cassé avec nouvelle cible), et mises à jour de cibles cassées (ancienne cible morte vs nouvelle cible en ligne). Évaluer le risque : `medium` pour la création individuelle de redirections ou de petites corrections (moins de 10 changements), `high` pour les imports groupés, les changements à l'échelle d'une migration (plus de 10 redirections), ou toute suppression de règles de redirection existantes.
6. **Exécuter via le MCP CMS** : Après approbation, déployer les changements de redirection via le MCP CMS connecté. Pour WordPress : créer ou mettre à jour les règles via l'API REST du plugin Redirection (préféré pour la journalisation et le suivi), le module de redirection RankMath, le gestionnaire de redirection Yoast Premium, ou la modification directe de `.htaccess` (dernier recours, avec sauvegarde). Pour Webflow : utiliser l'API de redirection 301 native avec support en masse pour les migrations. Gérer les contraintes spécifiques au CMS — la limitation 301-uniquement de Webflow, les formats de règles spécifiques aux plugins WordPress, et les différences de syntaxe de correspondance de motifs.
7. **Vérifier après le déploiement** : Tester chaque redirection créée ou modifiée en envoyant des requêtes HTTP vers les URL sources et en confirmant que le code de réponse (301 ou 302) et la destination finale correspondent à la spécification. Pour les corrections de chaînes, vérifier que la redirection se résout désormais en un seul saut. Pour les corrections de boucles, vérifier que la redirection atteint une page 200. Signaler tout échec de vérification pour investigation immédiate.
8. **Journaliser tous les changements via seo-executor.py** : Enregistrer chaque changement de redirection avec l'horodatage, le type d'action (création, mise à jour, suppression), l'URL source, l'URL cible, le type de redirection, l'état précédent (pour les mises à jour et corrections), la plateforme CMS et la méthode utilisée, le résultat de la vérification, et les instructions de restauration. Conserver l'état complet des redirections avant changement pour les opérations groupées afin de permettre une restauration complète si nécessaire.

## Résultat

Un rapport structuré de gestion des redirections contenant :

- **Confirmation de changement de redirection** : Chaque redirection créée, mise à jour ou supprimée — montrant l'URL source, l'URL cible, le type de redirection (301/302), l'action effectuée (nouvelle, chaîne corrigée, boucle résolue, cible mise à jour), et l'état avant/après pour les modifications
- **Rapport d'audit** : Total des redirections scannées, chaînes trouvées (avec le nombre de sauts et le chemin complet), boucles trouvées (avec le chemin du cycle), cibles cassées trouvées (avec les codes de statut HTTP), doublons trouvés, et score de santé global des redirections en pourcentage de redirections propres à saut unique
- **Résultats de vérification** : Test de réponse HTTP pour chaque redirection déployée — URL source confirmée, code de réponse reçu (301/302), URL de destination finale atteinte, nombre de sauts, et statut de réussite/échec. Tout échec est mis en évidence avec des détails de diagnostic
- **Entrée de journal d'exécution** : Enregistrement horodaté avec toutes les métadonnées du changement de redirection, les réponses de l'API CMS, l'instantané de l'état avant changement pour la capacité de restauration, la référence d'approbation, et les résultats de vérification pour la piste d'audit

## Agents utilisés

- **seo-specialist** — Analyse des redirections incluant la détection de chaînes, l'identification de boucles et le diagnostic de cibles cassées, validation des URL par rapport aux données historiques GSC et aux vérifications de statut en direct, planification de migration pour les opérations de redirection groupées, recommandations de type de redirection (301 vs 302) selon le cas d'usage, et stratégie de préservation du link equity pour la consolidation de redirections
- **execution-coordinator** — Exécution MCP CMS pour WordPress (API du plugin Redirection, redirections RankMath, redirections Yoast Premium, gestion .htaccess) et Webflow (API de redirection native avec support en masse), flux d'approbation avec évaluation des risques adaptée au volume de redirections et au type de changement, capture d'état avant changement pour la capacité de restauration, tests de vérification HTTP, et journalisation d'exécution avec piste d'audit complète
