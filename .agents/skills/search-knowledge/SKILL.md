# /digital-marketing-pro:search-knowledge

## Objectif

Recherche sémantique sur toute la connaissance de marque stockée dans la base de données vectorielle et le graphe de connaissances. Répond à des questions comme « Qu'est-ce qui a fonctionné pour l'email au T4 ? », « Quelles sont nos guidelines de voix de marque ? », « Montre-moi les apprentissages sur l'audience X », ou « Qu'avons-nous appris sur la tarification du concurrent Y ? » Retourne les entrées pertinentes classées par similarité avec un contexte de provenance complet, afin que les agents et les utilisateurs puissent prendre des décisions éclairées par tout ce que la marque a jamais appris — pas seulement ce dont ils se souviennent de la session en cours. Recherche simultanément dans toutes les couches de mémoire connectées : la base vectorielle pour la similarité sémantique, le graphe de connaissances pour les relations entre entités, et l'index local pour les entrées récentes non synchronisées.

## Entrées requises

L'utilisateur doit fournir (ou se voir demander) :

- **Requête de recherche** : Question ou sujet en langage naturel — par ex. « Quels motifs d'objet d'email ont généré le taux d'ouverture le plus élevé ? », « Quelles sont nos restrictions de conformité pour le marché UE ? », « Montre-moi tout ce que nous savons sur le concurrent X », ou « Quelles stratégies de campagne ont fonctionné pour l'audience millennials au T4 ? » La requête est vectorisée et comparée sémantiquement, donc le libellé exact n'a pas besoin de correspondre au contenu stocké
- **Filtre de type de contenu (optionnel)** : Restreindre les résultats à un type spécifique — `guideline`, `campaign-learning`, `competitive-intel`, `performance-insight`, ou `brand-asset`. Omettre pour rechercher tous les types. Plusieurs types peuvent être spécifiés sous forme de liste séparée par des virgules
- **Filtre de plage de dates (optionnel)** : Restreindre les résultats à une fenêtre temporelle — par ex. « 90 derniers jours », « T4 2025 », « 2025-01-01 à 2025-06-30 », ou « cette année ». Utile pour les requêtes sensibles à la récence où une connaissance plus ancienne peut être obsolète ou dépassée
- **Nombre maximum de résultats (optionnel)** : Nombre de résultats à retourner — 10 par défaut, maximum 50. Utiliser des limites plus élevées pour les requêtes de recherche exhaustive et les audits de connaissance, des limites plus basses pour les recherches factuelles rapides
- **Filtre de tags (optionnel)** : Restreindre davantage par tags spécifiques — par ex. « email », « paid-social », « audience-millennials », « black-friday ». Se combine avec le type de contenu et la plage de dates comme filtres ET pour une récupération précise
- **Filtre de priorité (optionnel)** : Filtrer par priorité de connaissance — `high` pour les insights mis en avant proactivement, `normal` pour les entrées standards, ou `all` (par défaut). Utiliser `high` lorsque seuls les apprentissages les plus impactants sont nécessaires
- **Inclure les entrées expirées (optionnel)** : S'il faut inclure les entrées de connaissance dont la date d'expiration est dépassée — `false` par défaut. Définir sur `true` pour la recherche historique où une connaissance obsolète conserve une valeur d'archive
- **Mode de recherche (optionnel)** : `semantic` (par défaut — similarité en langage naturel), `exact` (correspondance par mot-clé pour des termes précis comme les noms de campagne ou les valeurs de métriques), ou `hybrid` (combine les deux avec une pondération)

## Processus

1. **Charger le contexte de la marque** : Lire `~/.claude-marketing/brands/_active-brand.json` pour obtenir le slug actif, puis charger `~/.claude-marketing/brands/{slug}/profile.json`. Appliquer la voix de marque, les règles de conformité pour les marchés cibles (`skills/context-engine/compliance-rules.md`), et le contexte sectoriel. Vérifier également les guidelines à `~/.claude-marketing/brands/{slug}/guidelines/_manifest.json` — si présentes, charger les restrictions. Vérifier les SOP d'agence à `~/.claude-marketing/sops/`. Si aucune marque n'existe, demander : « Configurer d'abord une marque (/digital-marketing-pro:brand-setup) ? » — ou continuer avec les valeurs par défaut.
2. **Vérifier les services de mémoire configurés** : Exécuter `python "${CLAUDE_PLUGIN_ROOT}/scripts/memory-manager.py" --brand {slug} --action get-memory-status` pour voir quels backends de mémoire sont **configurés via des variables d'environnement** (ceci vérifie uniquement les variables d'environnement — cela ne teste pas l'accessibilité en direct ni la capacité). N'interroger que les backends effectivement connectés : une base vectorielle (par ex. Pinecone) pour la similarité sémantique, un serveur de graphe de connaissances pour les relations (si connecté), un stockage inter-sessions (si connecté), et l'index local toujours disponible. DMP n'en fournit aucun par défaut — l'index local fonctionne toujours ; le reste est opt-in.
3. **Exécuter la recherche vectorielle** : Si un MCP de base vectorielle (par ex. Pinecone) est connecté, l'interroger avec la requête de recherche de l'utilisateur, en appliquant les filtres de type de contenu, plage de dates, tags, et priorité comme contraintes de métadonnées. Demander les N meilleurs résultats classés par similarité cosinus avec les charges utiles de métadonnées complètes retournées.
4. **Exécuter la recherche en graphe (uniquement si un serveur de graphe est connecté)** : Si vous avez un serveur MCP de graphe de connaissances fonctionnel connecté (opt-in ; aucun n'est fourni par défaut), l'interroger également pour les relations entre entités et les chaînes causales pertinentes à la requête — par ex. « quelles campagnes ont influencé la croissance de l'audience », « quelle stratégie a remplacé notre ancienne approche », ou « comment le positionnement du concurrent X a-t-il évolué ». Les résultats de graphe apportent un contexte de relation et temporel que la recherche vectorielle seule ne peut pas capturer.
5. **Rechercher dans l'index local** : Exécuter `memory-manager.py --action search-local` pour vérifier l'index de mémoire local pour toute entrée pas encore synchronisée avec la base vectorielle. Cela capture les connaissances de session récentes qui ont été stockées localement via `/digital-marketing-pro:save-knowledge` mais pas encore poussées vers le stockage persistant via `/digital-marketing-pro:sync-memory`.
6. **Fusionner et classer les résultats** : Combiner les résultats de toutes les couches interrogées (base vectorielle, graphe de connaissances, index local), dédupliquer par hash de contenu, et classer par pertinence composite. Pondérer les scores de similarité vectorielle, la force de relation en graphe, la récence, et le niveau de priorité. Traduire les scores de similarité bruts en catégories de pertinence lisibles par l'humain (très pertinent, lié, faiblement lié).
7. **Présenter les résultats avec contexte** : Afficher les résultats classés avec la provenance complète — résumé du contenu, type de contenu, tags, source, date de stockage, catégorie de pertinence, priorité, et entrées liées. Pour les résultats de graphe, inclure les relations entre entités et le contexte temporel. Suggérer des requêtes de suivi basées sur les motifs observés dans les résultats.

## Résultat

Une réponse de recherche structurée contenant :

- **Interprétation de la requête** : Comment la requête en langage naturel a été analysée — concepts clés extraits, filtres appliqués (type de contenu, plage de dates, tags, priorité), mode de recherche utilisé, et quelles couches de mémoire ont été interrogées
- **Liste de résultats** : Entrées classées avec : catégorie de pertinence (très pertinent, lié, faiblement lié), résumé du contenu, type de contenu, tags, attribution de source, date de stockage, niveau de priorité, couche de stockage (base vectorielle, graphe, local), et statut d'expiration le cas échéant
- **Relations en graphe (le cas échéant)** : Relations entre entités découvertes — connexions entre campagnes, chaînes causales, séquences temporelles, chemins d'évolution de stratégie, et cartes de relation concurrentielle qui ajoutent un contexte structurel au-delà de la correspondance par mot-clé
- **Références croisées** : Liens entre les résultats — par ex. un apprentissage de campagne qui se connecte à un insight de performance et à une entrée d'intelligence concurrentielle, montrant l'image complète à travers les types de connaissance
- **Lacunes de connaissance** : Zones où la requête suggère qu'une connaissance devrait exister mais où aucune entrée n'a été trouvée — avec des recommandations spécifiques pour combler ces lacunes via `/digital-marketing-pro:save-knowledge` ou la collecte de données
- **Suggestions de suivi** : Requêtes affinées ou étendues que l'utilisateur pourrait exécuter pour explorer une connaissance liée — basées sur les tags, entités, et types de contenu trouvés dans les résultats actuels
- **Nombre de résultats par couche** : Répartition du nombre de résultats provenant de chaque couche de mémoire (base vectorielle, graphe de connaissances, index local) pour la transparence sur la couverture de recherche et le statut de synchronisation
- **Performance de la recherche** : Temps d'exécution de la requête par couche et au total, pour aider à diagnostiquer les recherches lentes ou les problèmes de connectivité avec les services de mémoire externes

## Agents utilisés

- **memory-manager** — Analyse de requête avec extraction de concepts et construction de filtres, exécution de recherche parallèle multi-couches (base vectorielle via un MCP connecté, graphe de connaissances via un MCP de graphe connecté le cas échéant, index local via le système de fichiers), déduplication des résultats par hash de contenu, fusion de résultats inter-couches avec classement de pertinence composite, traduction des scores de similarité en catégories lisibles par l'humain, extraction de contexte de relation à partir des résultats de graphe, détection de lacunes de connaissance basée sur l'analyse de couverture de requête, et génération de requêtes de suivi à partir de l'analyse de motifs dans les résultats
